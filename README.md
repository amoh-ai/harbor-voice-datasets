# harbor-voice datasets

Voice-agent benchmarks as [harbor](https://github.com/harbor-framework/harbor)
tasks, run with [harbor-voice](https://github.com/amoh-ai/harbor-voice).

Each folder under `datasets/` is one dataset, and each folder in it is one
task. A version is a commit: harbor-voice's
[`registry.json`](https://github.com/amoh-ai/harbor-voice/blob/main/registry.json)
pins every task of a dataset version to the commit it was released at,
tagged `v<version>`, so a published version never changes. A new version
rewrites the dataset's folder in a later commit.

## Run a dataset

From a harbor-voice checkout, which carries the registry its code was
released with:

```bash
git clone https://github.com/amoh-ai/harbor-voice && cd harbor-voice && uv sync
uv run eva-adapter job-config --hub-dataset eva@0.1.2 \
    --model openai.realtime/gpt-realtime-1.5 -o job.yaml
uv run harbor-voice jobs start -c job.yaml
```

`tau-voice job-config --hub-dataset tau-voice-control@0.1.2 …` does the same
for tau-voice. `job-config` adds what a plain harbor run lacks: one agent per
benchmark trial seed, the benchmark's own mean, and infrastructure retries.
Harbor downloads the tasks at their pinned commit; nothing here needs a clone.

Your keys come from your environment: tasks name them only as `${VAR}`
templates. The adapters' READMEs list what each benchmark needs, including
the one-time ElevenLabs setup.

## Datasets

| Dataset | Tasks | What |
|---|---|---|
| `tau-voice-control` | 278 | every tau2-bench task, `control` speech (clean, patient turn-taking) |
| `tau-voice-regular` | 278 | every tau2-bench task, `regular` speech (accents, noise, interruptions) |
| `tau-voice-control-test` | 100 | tau2-bench's `test` split, `control` speech |
| `tau-voice-regular-test` | 100 | tau2-bench's `test` split, `regular` speech: the τ-voice leaderboard's condition |
| `tau-voice-parity-control` | 40 | the tau-voice adapter's parity sample, `control` speech |
| `tau-voice-parity-regular` | 40 | the parity sample, `regular` speech |
| `eva` | 213 | every EVA record, clean audio |
| `eva-parity` | 60 | the EVA adapter's parity sample, 20 per domain |

The tau-voice datasets come from
[tau2-bench](https://github.com/sierra-research/tau2-bench) at `2174a60`, and
the EVA datasets from [EVA](https://github.com/ServiceNow/eva) at `039efa0a`.
How each adapter was checked against its original harness is in its
`PARITY.md` in harbor-voice.

## Images

Every task names prebuilt images on `ghcr.io/amoh-ai` by digest
(`…:tag@sha256:…`), so a version always runs the same bytes. From 0.1.1 the
images are built for `linux/amd64` and `linux/arm64`, so they run without
emulation on x86 backends and on ARM machines such as Apple silicon. 0.1.0
pins older images built for x86 only.

0.1.2 changes only the EVA tasks: they pass `VERTEXAI_CREDENTIALS` to the
sidecar, for EVA's Gemini judge on Vertex with a service account
(`eva-adapter judges --gemini vertex-json`). The tau-voice tasks are the same
as in 0.1.1.

| Version | Images |
|---|---|
| 0.1.2 | same as 0.1.1 |
| 0.1.1 | `tau-voice-runtime:2174a60-ce6c029644`, `tau-voice-main:413a7f6ab7`, `eva-sidecar:039efa0a-077f8e4f23`, `eva-main:413a7f6ab7` |
| 0.1.0 | `tau-voice-runtime:2174a60-3cefc407ea`, `tau-voice-main:c168c1f67a`, `eva-sidecar:039efa0a-21e9a0b06c`, `eva-main:c168c1f67a` |

## Contributing

Tasks are generated by harbor-voice's converters and never edited by hand. To
publish a version, follow "Publishing a dataset version" in harbor-voice's
CONTRIBUTING.md. Merge pull requests with a merge commit: a released commit
must stay reachable, or every version pinned to it breaks.

CI runs the same checks a contributor can run locally: the task rules
(layout, `${VAR}` templates, no keys, digest-pinned images), then harbor's own
`harbor lint` (the full command is in `.github/workflows/check.yml`).

```bash
uv run --no-project --with pyyaml python .github/check_tasks.py
```
