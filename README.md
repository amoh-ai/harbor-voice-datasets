# harbor-voice datasets

Voice-agent benchmarks as [harbor](https://github.com/harbor-framework/harbor)
tasks, run with [harbor-voice](https://github.com/amoh-ai/harbor-voice).

Each folder under `datasets/` is one dataset, and each folder in it is one
task. A version is a commit: harbor-voice's
[`registry.json`](https://github.com/amoh-ai/harbor-voice/blob/main/registry.json)
pins every task of a dataset version to the commit it was released at,
tagged `v<version>`, so a published version never changes. A new version
rewrites the dataset's folder in a later commit.

## Run a dataset

From a harbor-voice checkout, which carries the registry its code was
released with:

```bash
git clone https://github.com/amoh-ai/harbor-voice && cd harbor-voice && uv sync
uv run eva-adapter job-config --hub-dataset eva@0.1.0 \
    --model openai.realtime/gpt-realtime-1.5 -o job.yaml
uv run harbor-voice jobs start -c job.yaml
```

`tau-voice job-config --hub-dataset tau-voice-control@0.1.0 …` does the same
for tau-voice. `job-config` adds what a plain harbor run lacks: one agent per
benchmark trial seed, the benchmark's own mean, and infrastructure retries.
Harbor downloads the tasks at their pinned commit; nothing here needs a clone.

Your keys come from your environment: tasks name them only as `${VAR}`
templates. The adapters' READMEs list what each benchmark needs, including
the one-time ElevenLabs setup.

## Images

Every task names prebuilt images on `ghcr.io/amoh-ai` by digest
(`…:tag@sha256:…`), so a version always runs the same bytes.

## Contributing

Tasks are generated by harbor-voice's converters and never edited by hand. To
publish a version, follow "Publishing a dataset version" in harbor-voice's
CONTRIBUTING.md. Merge pull requests with a merge commit: a released commit
must stay reachable, or every version pinned to it breaks.
